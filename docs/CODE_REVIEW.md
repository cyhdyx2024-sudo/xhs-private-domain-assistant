# 代码与安全审查记录（2026-08-29）

本文档公开记录一次针对本项目的完整"红队攻击 + 场景实测 + 代码审查"，保持工程透明。

## 一、红队攻击（服务端，25 项）

对产品模式实例执行：鉴权绕过、跨租户越权（IDOR）、SQL 注入、存储型 XSS、路径穿越、
SSRF（含 userinfo@ 绕过、伪造后缀域名、内网地址）、CSV 公式注入、超大请求体、注册洪水。

**结果：鉴权、租户隔离、SQL 参数化、模型域名白名单（含 @ 绕过）、内网防护全部守住。**
发现并已修复：

| # | 问题 | 修复 |
|---|------|------|
| 1 | 超大请求体触发未捕获异常，连接被硬切且日志刷 Traceback | 返回 413 JSON |
| 2 | `/tenant/register` 应用层无限流（无 nginx 的自托管用户会被灌爆租户表） | 每 IP 每分钟 10 次（X-Forwarded-For 感知） |
| 3 | 线索 CSV 导出存在 Excel 公式注入面 | 前缀 `=+-@` 的字段加 `'` 转义 |
| 4 | 客户线索无删除接口（数据擦除权） | 新增 `POST /leads/delete`、`/leads/clear` |
| 5 | 默认非产品模式 + `CORS: *` + 服务端凭据回退 = 任意网页可把本机 Bridge 当免费 LLM 代理 | 产品模式改为默认开启；CORS 仅回显可信来源（XHS 域 / 扩展 / 本机）；`/reply` 对不可信来源直接 403 |

## 二、场景质量实测（10 个真实对话）

价格追问、愤怒客户、英文客户、多轮上下文引用、留资确认、提示词注入、诱导虚假承诺等 10 个场景。

**第一轮发现 P0**：客户问"你加我微信了吗"，AI 编造"已经搜索 abc123 提交好友申请了"——
守卫正则只防将来时承诺（"马上加"），漏了过去时虚构（"已经加了"），且状态检测门漏掉
"加我微信了吗"这类带代词间隔的问法。**已修复并加入回归测试。**
修复后 10/10 场景通过，无虚假承诺、无提示词泄漏、无重复索要联系方式。

## 三、静态审查（扩展 + 服务端，30 项）

完整审查 `content.js` / `safety.js` / `options.js` / `agent.py`。屎山评分 **6/10**：
不是垃圾堆（safety.js 拆分、textContent 渲染、串行/中止/签名机制都做得对），
但状态层正在悄悄腐烂。**已修复（服务端侧）**：

- `rewrite_fallback` 动作、"fallback_text"、"temperature" 之前被服务端完全忽略（双倍 LLM 成本的盲重试）→ 已实现
- 合法的短回复（<24 字）被 503 拒绝 → 阈值调整为 6，避免误杀

**已知未修（诚实列表，按危害排序）**：

| 严重度 | 问题 | 计划 |
|--------|------|------|
| P1 | 多标签页可对同一会话重复自动发送：`processedMap`/`hourlySendTimestamps` 不在 storage 同步白名单里，两个窗口各自调度 | 引入 `store.js` 单一状态所有者 + 跨 Tab 仲裁 |
| P1 | 401 后设置页自动重新注册新工作区，旧租户的知识库/案例/线索静默"消失" | 服务端加按名恢复/令牌重签流程；客户端 401 不自动注册 |
| P1 | 消息时限门可能被消息正文里的 "14:00" 字样欺骗（时间戳从整卡 innerText 解析） | 时间戳只从专用时间节点提取 |
| P1 | A 客户的人工编辑草稿在切会话后残留到 B 的输入框（错发风险） | 切会话时无条件快照并清空 |
| P2 | 同名昵称会话共用去重键；不确定发送不计入每小时上限；多个 Map 无界增长；重注入监听器泄漏；活动检测误判等 | 随 store.js / scheduler.js 重构一并处理 |

## 四、重构路线（屎山治理，按收益排序）

1. **`store.js`**：单一状态所有者——schema 驱动的同步白名单（现在新配置键要改 4 处，已经漂移过一次）、
   读改写助手、跨 Tab 仲裁。一次解决多 Tab 重复发送、无界 Map、监听器泄漏三类问题。
2. **`xhs-dom.js`**：把所有 DOM 抓取/注入收口到带 fake-DOM 测试路径的接口后面，让 DOM 层像 safety.js 一样可测。
3. **`scheduler.js`**：定时器、活动检测、退避 Map、熔断、小时账本收口，统一内存上限。

结论：现在不做大爆炸重构——量级未到；先按上面的顺序拆，每拆一层补一层测试。
